# AGENTS.md — rtmupdate (update check library)

## What This Component Is

The library behind the update check of `rtmcli` (`check-update`, RTM-137) and `rtmapp` (the update
notice, RTM-138), part of epic RTM-130. It fetches the release list the website publishes,
`https://rtm.brcha.com/releases.json` (generated by the site build, see
[`site/AGENTS.md`](../site/AGENTS.md)), and says whether a release newer than the running one
exists on the user's channel. No UI, no binary.

## Conventions

- **The file:** `{"schema": 1, "releases": [{"version", "channel", "date", "url"}]}`. The schema
  is read first, on its own; any other value is `Error::Schema`, so a later format never makes a
  client claim it is up to date. `rtmcli` prints that error; `rtmapp` shows nothing.
- **Selection (`newest`):** the highest release above the running version that the channel is
  offered. `Stable` is offered stable releases only, `Beta` stable and beta releases. Versions
  compare as semver, so `26.2.0-beta.1 < 26.2.0 < 26.2.1`. Entries with an unknown channel or an
  invalid version are skipped, unknown fields ignored, `date` unused.
- **The request (`check_at`):** one blocking GET with a 5 s limit on the whole call and the fixed
  User-Agent `rtm-update-check`. No version, identifier, cookie or query string is sent; the host
  sees only the client's IP address. Redirects are followed, to other hosts too (the domain move
  of RTM-132). Callers with a UI run it on a thread of their own.
- **`RTM_UPDATE_URL`:** `url()` reads it and returns it instead of `URL` when it is set and not
  empty (tests that run a program, staging, a domain move); `check` uses `url()` on each call.
  rtmapp resolves `url()` once at start and passes it to its check, so its in-process tests can
  use a local server. The crate's own tests call `check_at` directly and never set it.
- **Dependencies:** `ureq` 3, blocking, with rustls, ring and webpki-roots (Mozilla's root
  certificates, bundled): no async runtime and no OpenSSL, unlike `reqwest` (tokio) or
  `native-tls` (OpenSSL on Linux). The OS certificate store is not used; a proxy with its own CA
  makes the check fail, which callers treat like being offline.
- **Nix:** the Nix packages build `rtmcli` and `rtmapp` without the update check (the
  `update-check` feature RTM-137 and RTM-138 add stays off), since Nix users update through Nix.

---

## Important Notes

- **Tests** never use the network. `update_http_tests.rs` serves canned answers from a
  `TcpListener` on `127.0.0.1`: an answer, a redirect to `localhost` (bound to the first address
  `localhost` resolves to, often `::1` on macOS and Windows), a 404, a server that never answers
  (the test takes about 5 s), and a closed port.
